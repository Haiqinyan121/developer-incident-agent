# Redis 连接池超时排障手册

## 常见症状

- 应用日志出现 `connection pool timeout`、`too many connections` 或获取连接耗时持续升高。
- 请求延迟上升，但 Redis 服务进程仍然存活。
- 活跃连接数接近连接池上限，等待连接的请求持续增加。

## 排查顺序

1. 检查连接池上限、活跃连接数、空闲连接数和等待队列长度。
2. 区分 TCP 建连超时、连接池耗尽和 Redis 命令执行变慢。
3. 检查连接是否在异常路径中正确归还，确认是否存在连接泄漏。
4. 查看 Redis 慢查询、CPU、内存和网络延迟，判断瓶颈是否来自服务端。
5. 在确认下游容量允许后再调整连接池大小，避免只扩大连接池掩盖泄漏。

## 处理原则

不要把所有超时都归因于 Redis 服务不可用。连接池耗尽也可能由上游并发突增、请求未释放连接或下游响应变慢引起。没有监控数据时只能给出候选原因，不能直接确认根因。
